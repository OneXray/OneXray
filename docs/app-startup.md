# App 启动行为

本文区分三个容易混淆的设置：登录时启动 App、桌面端隐藏主窗口、App 启动后自动连接。三者彼此独立，默认都关闭。

## 设置范围

| 设置 | 平台 | 作用 |
| --- | --- | --- |
| 登录时启动 | macOS、Windows、Linux | 向操作系统注册或取消 OneXray 登录项 |
| 启动时隐藏 | macOS、Windows、Linux | 桌面窗口准备完成后保持隐藏，托盘仍可使用 |
| App 启动时连接 | 全平台 | 服务准备完成后连接默认配置 |

隐藏启动不是命令行参数，也不要求登录时启动已开启。用户手动打开 App 时，该设置同样决定初始窗口是否可见。

## 启动顺序

1. 启动早期读取“App 启动时连接”和“启动时隐藏”；读取失败按关闭处理。登录项状态不来自启动偏好，由设置页向操作系统查询。
2. 桌面窗口准备完成后，根据“启动时隐藏”显示或隐藏窗口。
3. `LaunchBootstrapService` 只检查隐私确认和首次初始化标记；任一未完成都进入同一个 Setup 流程，否则进入 Connect。它不打开数据库、不发布 Geodata，也不初始化连接服务。
4. 首次初始化只有隐私确认和合并配置两个步骤。`SetupService` 复用本地存储与 Geodata 准备能力，在同一配置页选择国家/区域，以及 Windows/Linux 的出口网卡；其它平台不显示网卡选项。Setup 不检查或申请 VPN 权限，不提供添加服务器步骤，也不启动 VPN。
5. 进入正常主界面时，主 Shell 先以 `ServiceManager` 作为唯一就绪门，依次完成 `StoragePreparation`、Geodata 发布校验和平台运行前置条件检查；初始化成功前不构建四个业务页面，失败停留在主 Shell 的重试界面。`ConnectionCoordinator` 随后读取 VPN 状态和 VPN、Android 局域网及 System Extension 权限；缺少必要授权时主动申请一次，等待结果后重新读取原生状态，再完成主界面初始化。此过程不依赖是否有服务器，也不启动 VPN。正常启动不依赖 Setup 曾执行这些步骤。托盘在普通服务初始化阶段创建；所有服务准备完成后刷新托盘状态。连接页只管理自身数据与页面可见期间的实时流量读取。
6. 若允许自动连接，调用连接协调器完成资源和节点准备，再启动已保存的普通或 Raw 配置。已有服务器或有效 Raw 时，首页可直接连接。
7. 关键启动准备失败、就绪后的托盘刷新失败或自动连接失败时显示主窗口，让用户可以处理错误；“启动时隐藏”不能遮蔽失败和重试入口。辅助服务初始化独立捕获并记录错误，不一概阻断主界面。

隐私协议与首次初始化会抑制本次进程的自动连接，并要求显示主窗口。该抑制不改写保存的偏好。
隐私正文使用 HTTPS 页面，不在 App 内托管。

移动端在启动早期注册 `quick_actions` 回调。冷启动收到的快捷操作先等待主 Shell 服务就绪，
同时抑制本次进程的偏好自动连接，避免“停止”或“切换配置”意外触发连接；不改写用户偏好。
就绪后消费一次待处理操作；启动失败时保留到重试成功。热启动直接交给已就绪的页面入口，
同一种正在执行的快捷操作不重复提交，“停止 VPN”不被正在执行的“启动 VPN”阻塞。
完整菜单与业务边界见 [系统快捷入口](app-navigation.md#系统快捷入口)。

Geodata 在进程内首次准备时通过文件访问队列安装与恢复；Setup 进入主界面及打开 Geodata 页时，
已准备完成的数据只做完整性读取检查，不等待或中断导入后的后台测速。目录或发布数据完整
丢失时仍通过文件访问队列重建，部分损坏保持报错。普通启动不暂停后台模块；只有
清空流程暂停相关模块、取消未开始的任务并等待必要的在途操作，具体协调见 [数据管理](data-management.md)。

Setup 内不自动前进：隐私需主动同意，配置页点击“进入首页”才保存并完成初始化。
Windows/Linux 必须明确选择当前存在的出口网卡，不默认选择第一张；列表选中即返回配置页。
地区允许不选择，保留原配置；地区识别只预选候选地区，不能把默认 CN 当成识别结果。
区域选择直接复用智能路由的直连地区页面，使用同一份已安装 Geodata 列表、搜索、单选和
“完成”操作；完成后只更新 Setup 草稿，返回或取消不改选择。主动清空后确认会保存空的
直连地区列表，不等同于未选择。网卡与地区在完成初始化时一起保存，保存成功后才写入
首次初始化完成标记；失败保留草稿供重试。
Setup 不读取或监听服务器列表，不依赖已有节点或测速结果；服务器在进入主界面后添加。
已完成首次初始化的用户正常启动时直接进入主界面；未完成时根据隐私确认和首次初始化
标记恢复欢迎或配置页，不再单独持久化步骤序号。
首次运行标记只用于启动时选择入口，不限制已进入 Setup 的配置保存。确认隐私后仍由用户
完成配置；即使已有完成标记，“进入首页”也执行必要的隐私、网卡和地区校验，保存成功后
再写入完成标记并导航，不因页面步骤与持久化标记不同而拒绝保存。

## 平台前置条件与权限

正常启动每次都检查当前平台事实，不能以 Setup 已完成作为授权或运行环境仍然有效的证明：

- 原生桥初始化必须返回非空的绝对数据根目录；Apple App Group 容器不可用等错误在任何数据库或 Geodata 访问前直接失败，不能退化为相对目录。
- Android 与 Apple 平台查询系统 VPN 授权；Android 17 及以上还检查 `ACCESS_LOCAL_NETWORK`，macOS System Extension 还查询扩展授权状态。
- Windows 默认 EXE 模式检查 libXray、Core 和 Wintun，使用用户 Application Support 数据根目录；MSIX 模式检查包身份与 VCore，使用 package 数据根目录，失败不回退到非打包目录。Linux 检查 Core 可执行权限、`/dev/net/tun` 以及 `cap_net_admin` / `cap_net_raw`。
- Windows/Linux 每次实际连接前按已保存名称检查 Xray 出口网卡：先停止旧运行，再检查网卡；未设置或当前列表中不存在时，在启动新 VPN 前失败并提示重新选择。连接建立后不持续监测网卡状态。
- 正常主界面初始化时，对尚未就绪的 VPN、Android 局域网或 System Extension 权限主动申请一次；已有授权或原生返回“不需要”时不申请。用户拒绝、取消或仍需在系统中批准时，仍允许进入首页，保留手动连接时的授权重试，不把权限未就绪当成服务初始化错误。同一进程重复进入主界面不重复申请；回到前台和日常状态刷新只查询，不自动重复弹框。
- Android 通知权限仍由 `NotificationService` 在服务初始化时管理。扫码相机权限属于扫描动作，在进入扫码功能时请求，不属于启动前置条件。

Swift 使用 `targetEnvironment(simulator)` 判断模拟器，权限查询和申请均返回“不需要”，
VPN 安装检查视为通过，不调用不可用的 NetworkExtension VPN preferences IPC。
正常启动与恢复前台统一消费原生结果；iOS 真机的 Debug 和正式构建均执行正常授权检查。
Android 17 及以上在主界面初始化或连接页手动重试的同一授权动作中依次请求 VPN 和局域网权限，两者就绪后才允许连接。
局域网权限被拒绝时保留授权入口；被永久拒绝时，再次点击入口打开系统 App 设置，返回后重新检查。
局域网授权状态直接读取系统，不写入初始化完成标记；旧版 Android 不检查或申请这项权限。

## 存储冷启动恢复

`StoragePreparation` 只负责打开数据库、完成必要迁移，并缓存本次进程首次准备时的缺库信号。
打开失败后释放失败连接，允许正常启动重试；不查询、停止或等待 VPN，也不生成升级快照。
数据库版本检查与事务迁移统一由 `AppDatabase` 处理，正常权限与 VPN 状态检查仍由连接初始化负责。

`ServiceManager` 在启用外部命令和自动连接之前处理数据库或整个 `dat` 目录丢失，使用
内置资源重建默认路由数据，不依赖网络或 Setup。部分损坏或未登记文件不能被当作完整
存储丢失而静默清理；具体恢复边界见 [数据管理](data-management.md#冷启动重建)。

## 各平台登录项

### macOS

原生层使用 `SMAppService.mainApp`。状态可能是已启用、已关闭、需要用户批准、不可用或错误；需要批准时，界面可以打开系统的登录项设置。Dart 侧通过 Pigeon 调用原生实现。

### Windows

编译期 `ONEXRAY_WINDOWS_MODE` 默认 `exe`，可显式设为 `msix`；不提供用户设置或自动模式降级。
EXE 安装包和 ZIP 共用 EXE 模式。EXE 使用当前用户 Startup Folder 的 OneXray 快捷方式，保留
v26.8.4 的登录项行为；只修改自身或已失效的 OneXray 快捷方式，不覆盖另一份有效安装的登录项。
ZIP 不改变数据根目录，也不自动注册 URL 协议。EXE 只在实际启动或需要提权停止 Core 时请求 UAC，
普通初始化不为权限检查启动 Core，Flutter 主进程不要求管理员权限。

Microsoft Store MSIX 注册默认关闭的 package `StartupTask`，TaskId 为 `VCoreStartup`。Dart 通过
`vcore.dll` 查询、申请启用和关闭任务；用户或策略阻止启用时，设置页引导打开 `ms-settings:startupapps`。
该模式要求 package identity，不读取或迁移 EXE 快捷方式。两种登录项都只负责登录后启动 App；
是否隐藏窗口和是否连接 VPN 仍分别由对应偏好决定。

### Linux

App 在 XDG autostart 目录管理 `net.yuandev.onexray.desktop`。优先使用 `XDG_CONFIG_HOME`，否则使用 `$HOME/.config`；无法确定目录时报告不可用。现有条目的 `Exec`、`TryExec` 或可执行文件无效时视为失效。

## 桌面窗口与退出

- 关闭主窗口只隐藏窗口，不退出 App，也不停止 VPN。
- macOS 与 Windows MSIX 的托盘同时提供 `Quit` 和 `Quit and Stop VPN`：前者只退出 App，
  不发送停止 VPN 命令；后者通过连接协调器停止 VPN，成功后再退出。MSIX 的 VPN / Core
  生命周期由独立的 Provider / Session Host 管理，不依赖前台 App 存活。
- Windows EXE（含 ZIP）与 Linux 保留单个 `Quit`，先停止 VPN，再退出 App。
- 需要停止 VPN 的退出操作如果失败，保持 App 运行并显示主窗口，保留失败状态供用户重试。

## 清理与失败边界

- 清理 App 数据且准备删除用户偏好时，必须先取消当前平台登录项；取消失败时停止破坏性清理。Windows 按编译模式取消自身快捷方式或当前 MSIX 的 StartupTask，不互相清理。
- 清理成功后由清理流程重新发布内置 Geodata 与数据库元数据，再直接返回连接首页；不重置隐私和首次初始化标记，也不借助 Setup 或重启恢复运行不变量。
- 登录项注册状态由操作系统事实决定，不能只依据 Preferences 显示。
- 自动连接只执行一次。重复的服务就绪事件不得重复启动 Core。
- 自动与手动连接使用同一协调器；配置准备、原生启停、失败状态与运行输入遵循
  [连接生命周期](xray-configuration.md#运行协调与统计)。
- 连接页直接操作失败由页面反馈；通过移动端快捷方式或桌面托盘启动失败时额外发送系统通知，确保 App 不在前台时仍能看到结果。Apple 通知权限在发送此类通知时按需申请。
- 连接页状态、操作提示与托盘/快捷方式通知共用错误映射，保留节点解析失败的原因和可用数/所需数；无可用接入节点时提示添加服务器，不额外执行一套托盘节点检查。普通状态刷新不抹掉上次失败详情，成功连接后清除。
- 托盘因无可用节点或节点数量不足而启动失败时只通知，不强制显示主窗口；通知发送失败也不改变此窗口策略。授权、出口网卡等需要用户处理的错误仍显示主窗口。取消连接不发送失败通知；停止与退出失败继续保留主窗口重试入口。

## 主要实现入口

- 启动编排：`lib/service/launch/app_startup.dart`
- 平台分发：`lib/core/desktop_startup/`
- 隐私与首次初始化路由：`lib/service/launch/bootstrap.dart`、`lib/pages/launch/`
- 正常服务初始化：`lib/service/manager.dart`
- 偏好：`lib/core/constants/preferences.dart`
- 存储准备：`lib/service/launch/storage_preparation.dart`
- 首次初始化：`lib/service/launch/setup.dart`
- 平台前置条件与权限：`lib/service/connect/platform_requirements.dart`
- 连接协调：`lib/service/connect/coordinator.dart`
- 系统 GeoData：`lib/service/advanced/xray/geodata/service.dart`
