# 连接配置备份

备份入口位于设置的数据区；连接和服务器的空状态也提供“从备份恢复”，在当前 Tab 内打开同一备份页面，
不直接执行恢复或授权覆盖。仅在支持备份的平台显示这些入口。
只管理一个可覆盖的配置文件，不提供版本列表、双向同步或云账号登录。
新文件使用 `OneXray-backup.json`；Android 以系统返回的文档 URI 为目标，展示提供商实际返回的名称。
备份未加密，包含节点凭据、订阅地址、Age 私钥及 HWID；Base64 不提供保密性。
首次允许写入某个目标前必须确认敏感信息与后续覆盖风险。

## 平台存储

| 平台 | 目标与实现 | 原生补充边界 |
| --- | --- | --- |
| iOS / macOS / macOS SE | `iCloud.net.yuandev.onexray` 文档容器中的 `Documents/OneXray-backup.json`；`icloud_storage_plus` 协调读写 | 不实现第二套 Swift/Pigeon 内容读写 |
| Android | SAF 单文档，用户可在系统选择器选择 Google Drive；`saf_stream` 内容读写 | Pigeon 只负责选择/创建、持久读写授权检查及释放授权 |
| Windows EXE / ZIP / MSIX | 用户选择的 OneDrive 同步目录，普通文件读写 | 不接 OAuth / Graph，不要求 package identity |

Linux 不显示备份入口。普通配置导入/分享与备份互相独立，不让普通导入器猜测备份格式。
选择目标或读取已有备份不授予覆盖许可；新安装不会静默覆盖其他设备留下的文件。
解除绑定或清理 App 数据不删除云文件；更换目标清除旧目标的许可和本机时间记录。

写入成功只表示本地容器或提供商接受了内容，不表示云同步已经完成。
Apple 和 Windows 使用替换写入；Android 使用固定 URI 覆盖，不主动先删除旧文件，
但不承诺所有文档提供商具备原子替换能力，中断可能损坏旧文档。

## 协议 v1

UTF-8 JSON 根部的 `format` 固定为 `onexray-backup`，`version` 为 1，`createdAt` 为 Unix 毫秒。
必要分区是 `coreConfigs`、`subscriptions`、`routingProfiles`、`smartRouting`、`geoData`，
缺失列表不等于空列表。字段定义以 [备份模型](../lib/core/backup/model.dart) 为唯一来源。
旧 ZIP v3/v4 不在导入范围，不按同名 version 猜测旧协议。

- `coreConfigs` 只保存本地（`subId = 0`）outbound 和 Raw，保留全部旧 Raw，包括超过三份的记录。
- `subscriptions` 保存来源、原有 Age 密钥对和 HWID；即使 HWID 发送开关关闭也不丢标识。
  不保存订阅节点缓存、订阅节点的本地修改及成功更新时间。
- `routingProfiles` 保留常规/高级类型和原文，共用现有名称约束及三份上限。
- `smartRouting` 显式保存连接所需设置，不保存最终出口选择。最终出口若是本地节点，仍作为普通节点备份。
- `geoData` 只保存自定义来源的名称、类型和 HTTPS URL，包含待下载来源，省略默认组。
- 配置 `data` 保留数据库 Base64 字符串，不解码重排后写回，不经过分享链接或常规模型裁剪 Raw/高级内容。
- 不保存任何文件、数据库 ID、收藏、测速/位置缓存、首页当前选择、专家模式状态、平台策略或 App 偏好。

读写接受上限为 64 MiB，错误不部分恢复、不静默丢条目。校验格式、版本、类型、名称、
Base64/UTF-8/JSON 对象和现有路由存储边界；不重复实现 Xray 协议校验。
恢复不调用 TestXray，不要求下载成功，也不证明恢复后的配置能够启动。

Android 分块读取并在 finally 关闭句柄；Windows 限额读取。Apple 仅在手动读取时做一次大小预检，
之后再检查实际字节长度；插件仍会整文件分配，不能把预检当成硬性内存上限。
插件元数据调用的主线程风险没有通过 Dart isolate 消除，云占位文件行为仍需设备验收。

## 恢复与缺失资源

完整读取后先展示资产数量、待下载资源和同名冲突；此时不改库、不停 VPN、不下载。
用户确认后完整替换连接资产，不合并，合法空备份会清空现有连接资产，确认页明确说明。

恢复复用清理/恢复专用的互斥与模块暂停边界，等待必要在途操作、确认 VPN 停止后，
在同一数据库事务替换资产并生成新 ID；不重置自增序列，不让旧编辑或旧回包写回新资产。
停止失败不替换，提交失败按数据库事务及 Geodata 局部文件日志回滚，不自动重启旧 VPN。
保持目标设备当时的运行策略、主题语言、系统授权和备份设置，重置为普通模式、自动选节点、
智能路由，最终出口和 Raw/Custom 当前选择清空。恢复完成不自动连接，也不立即覆盖云备份。

恢复完全不依赖网络。默认 Geodata 使用当前有效文件或正常启动已准备的内置资源；
自定义来源只有名称、类型、URL 完全一致且文件有效才复用。其他来源登记为待下载，
同名异源必须在预览中提示，提交前重新检查冲突。旧自定义文件只按本次差异移除，
不整体清空 DAT 目录。文件处理及冷启动恢复见 [数据管理](data-management.md#geodata-发布)。

待下载项不会阻止首页初始化。依赖它的连接准备明确报告缺失文件，不静默删规则、改直连或下载兜底。
用户可先使用其他配置连接，再手动下载，或等待已连接状态下的现有自动更新。
订阅恢复后只有来源，需要通过现有订阅更新获取节点；当前恢复操作不自动追加刷新或测速任务。
证书等外部文件不在协议中，需用户另行准备。

## 自动备份

默认开启、可关闭，只有当前目标已经明确确认才写入。首次确认后执行首份备份；关闭自动备份
仍可手动备份。备份周期在本机独立保存，直接在备份页选择，默认 3 天，可选 1/3/7 天。
仅时间选项与 Geodata 相同；修改任一周期或开关均不影响另一功能，也不共用成功时间或 VPN 条件。
关闭自动备份后仍可预先调整周期；修改周期不立即写入，下次正常检查按新周期判断到期。

启动就绪、回前台、每小时、连接成功延迟检查分别判断到期；与订阅/Geodata 下载独立分发，
不等待下载，不要求 VPN，不建立系统后台任务。进程挂起或退出时不承诺准点执行。
手动/自动写入成功都推进本机成功时间；自动失败至少间隔一小时再尝试，手动不受节流限制。
不新增重试定时器、积压任务或持久化错误历史。

重复检查不排队。关闭开关阻止尚未提交的自动写入，提供商已经接受的写入允许完成。
目标变更与备份操作互斥；清理/恢复暂停新操作并等待在途写入，但不锁住整个 App。
自动失败只留在备份页供查看/手动重试，不弹窗、不抢窗口、不改变 VPN 或阻断服务初始化。
页面加载和未到期检查只访问本机偏好，不探测云文件。

## 实现与验收

- 协议与存储适配：`lib/core/backup/`；Windows 本地替换复用 `lib/core/tools/atomic_file.dart`。
- 资产与流程：`lib/service/settings/backup/`；清理协调：`lib/service/settings/data_cleanup.dart`。
- 页面：`lib/pages/settings/backup/`；调度：`lib/service/advanced/xray/data_update/scheduler.dart`。
- Android 选择授权桥接：`pigeon/message.dart` 与 `android/app/src/main/kotlin/net/yuandev/onexray/pigeon/BackupApi.kt`。

纯 Dart/Widget 测试和编译不能替代签名设备、真实 Drive/iCloud、云占位文件、撤权、覆盖及跨设备同步验收。
Windows 三种分发形态也必须在 Windows 验证，具体结果与发布阻碍记录在
[开发计划的验收矩阵](../plans/cloud-backup.md#102-平台人工验收)。
