# App 校验逻辑精简实施计划

状态：P0–P7 本机实施与回归完成；SE 实机及其他平台人工验收项见文末，未全部验收。
核对日期：2026-09-30；源码基线：`9c17fb3f`，分支 `dev-26.10.2-1`。

本计划记录本轮实施范围、验收标准和实际结果；当前行为以
[文档索引](../docs/README.md) 中的合同为准，后续改动不得将本轮结果当作新版本的验证结果。
用户已授权逐阶段实施、验证和 commit；不 push，不以源码审查代替测试结果。

## 1. 目标与范围

在保持有效配置、UI 操作、数据格式和平台行为不变的前提下，减少重复解析、重复查询和
跨层重复校验。将局部 Geodata 损坏的影响限定到相关数据或使用该数据的操作，不能让一个
无关文件阻断整个管理页、备份预览或不依赖它的配置。

主要收益是降低维护成本和失败路径复杂度；索引与备份重复解析的减少属于附带收益。
不设置未经测量的性能提升比例，也不以删除 `if`、`validate` 或测试的数量作为验收指标。

本轮范围是 OneXray 的 controller、service、core 及 macOS SE 文件传输边界。允许调整
内部参数、返回值和必要的 UI 数据绑定，不改页面结构或产品选项。不修改 libXray、Xray-core、
VCore，不更新依赖、数据库 schema、备份协议版本或本地 HTTP API 版本，不重编内核。
若实施证据表明必须突破这些边界，先记录阻碍并请求确认。

继续保留已经收敛的行为：

- 连接启动直接编译并启动 Core，不增加 `testXray` 启动预检；编辑、手写导入和配置校验仍使用 libXray。
- 不恢复 App 自写的节点协议、加密算法、端口或路由条件语义校验；合法性由内核判断。
- 启动不校验整个 Geodata 目录，不依赖下载兜底。自动更新只在 VPN 已连接时执行，
  失败保留旧文件，不修改 VPN 状态或触发重连；手动及导入依赖下载保持独立。
- 不恢复全局 `DataMaintenance`、统一 VPN 状态缓存、运行计划、快照或失败后重启旧 VPN。
- 常规配置仍由类型模型构造；高级自定义和完整 Raw 使用独立路径，保留各自的字段边界。

## 2. 校验职责

“只检查一次”针对同一次操作中没有变化的输入，不表示缓存一次结果后永久信任。
异步等待、用户确认、连接队列、文件发布和事务提交之间，相关事实可能变化，仍需在真正使用时检查。

| 对象 | 主要负责层 | 精简方向 | 必须保留 |
| --- | --- | --- | --- |
| 表单与编辑草稿 | 页面反馈，所属 service 决定能否保存 | 页面复用规则，不另写一套业务校验或重复查询数据库 | 即时错误、按钮 loading、离页与草稿修订保护 |
| 配置文本 | 对应配置解析入口 | 原文、解析对象和诊断在同次操作中传递，不反复编码再解析 | JSON 根结构、名称、编辑器可表达范围、托管字段边界 |
| Xray 配置语义 | libXray | 共享最小验证投影，不在 Dart 重做内核检查 | 真实内核错误、必要资源路径、原文诊断 |
| 保存与资产约束 | 所属 service 和最终数据库事务 | 合并同一保护范围内的重名、限额和原记录查询 | 提交时的重名/限额、记录已变更或删除、原子提交 |
| 原生响应 | `AppHostApi` 等桥接边界 | 业务层消费明确类型，不再次包装为动态 JSON 检查 | 失败响应、必要响应结构和可定位错误 |
| Geodata | Geodata 服务和文件队列 | 按用途读取，复用同一次受控发布中的索引结果 | 下载验证、文件安全、冲突、发布及回滚 |
| 平台网络与权限 | 平台策略和 Native | 同次保存复用有效的运行投影，不跨请求缓存系统事实 | IP 地址族、CIDR、网卡存在、系统权限和实际启停确认 |
| 外部 API、文件与备份 | 各自入口 | 入口只做本模块需要的格式与安全检查 | 鉴权、路径、大小、版本、授权及恢复事务 |

不建立通用 `ValidationManager`、永久“已校验”标记或第二套领域模型。优先修改现有方法，
只在需要传递原文与解析对象时增加小型内部结果；可变 Map/List 不因为经过一次检查就变成可信的不可变数据。
`XrayJson` 模型文件继续只包含字段与必要的 `fromJson` / `toJson`。

### 不能作为冗余删除的检查

1. 自定义名称、Custom 三份上限、Raw 新增上限与超额旧 Raw 保留、空接入槽数量、
   常规表单和高级模板的可表达范围。否则导入后会静默丢字段或改变用户配置。
2. 等待后的原记录/来源复核、订阅与测速的过期结果保护、最终事务冲突检查；不能用
   进入页面时读过数据库来代替。避免已知无效输入触发停止 VPN 的低成本预检仍可保留。
3. HTTPS 及逐跳重定向约束、HWID 拒绝结果与跨源移除、Age 密钥成对输入、零有效节点保旧。
4. HTTP API 的 Token、Host、Origin、方法和大小限制，以及读完请求后的凭据/服务状态复核。
   不同边界的大小限制保护不同分配与传输过程，不能仅因数值相同就合并删除。
5. Geodata 文件名、保留名称、路径穿越、符号链接、暂存目录清理范围与事务完整性。
   完成的导入事务不能再次使用，失败的草稿仍可重试。
6. 绝对数据根目录、受支持的正式数据库迁移、平台权限与网卡、Windows 网络策略限制。
   Android 仅所选应用模式下零个有效应用必须失败，不能退化为所有应用进入 VPN。
7. Widget、Tile、自动化及 Apple 按需连接可绕过 Flutter 页面，原生入口需要的运行检查不能
   因 Dart 已检查而删除。VPN 状态仍来自原生，发送停止命令不等于已停止。
8. 用户授权覆盖备份、停止 VPN 后才替换资产、敏感信息不进入错误日志等既有保护。

| 阶段 | 交付重点 | 依赖 | 当前状态 |

| P7 | 跨入口回归与文档收口 | P1–P6 的本机检查 | 本机回归完成；人工项已列明 |

本轮按顺序连续推进；每阶段先完成最小完整改动和对应回归，再进入下一阶段，
不反复询问是否继续。沿用阶段提交约定：验证通过后提交本阶段 OneXray 改动，不夹带其他任务
的改动，不为未修改的仓库创建空提交。push、PR、tag、发布和商店操作仍需当次授权。
阶段提交已获授权；不自动执行其他 Git 写操作。

每阶段执行同一流程：

1. 复核源码和受影响调用者，确认入口、输出及错误行为；已有实现只补缺口，不照旧清单重做。
2. 用已有测试固定受影响的正常、失败及并发边界，缺少证据时补少量回归，不建设大型测试框架。
3. 完成该阶段的生产代码与调用者调整，删除失去用途的内部包装及测试替身，保留真实业务断言。
4. 串行运行相关生成、格式化、分析和测试，记录实际结果及未验证平台；更新当前行为合同。
5. 提交并记录结果，自动进入下一阶段。计划性平台限制记为“待人工验收”，不冒充通过，
   也不阻断与该平台无关的后续工作。

出现新的测试/编译失败、数据保留风险或未明确的语义变化时，停止阶段推进，先定位并说明问题。
错误未解决不能标为通过或通过跳过测试继续；需要更改产品合同、外部协议或扩大仓库范围时请求确认。
既有失败在 P0 单列，不归入新改动；若会掩盖当前阶段的回归，同样先处理阻碍。

Flutter/Dart 全局串行，发现用户新开的运行会话先询问，不复用历史停止授权。
最小验证工程、运行日志和隔离数据放在工作空间 `references/validation-simplification/`，
不用系统临时目录，不接触开发者主库、正式 Geodata 或云备份。
长期回归优先加入仓库现有测试，新增独立 Demo 只验证现有测试无法覆盖的风险点。

## 5. P1 精简结果检查与桥接边界

主要入口：[订阅服务](../lib/service/servers/subscription/service.dart)、
[批量写入](../lib/service/shared/db/config_writer.dart)、
[CoreConfig DAO](../lib/core/db/dao/core_config.dart)、
[分享解析](../lib/service/shared/share/xray_share_reader.dart)、
[原生桥](../lib/core/pigeon/host_api.dart)、[运行准备](../lib/service/connect/preparation.dart)。

### 开发步骤

1. 删除订阅导入/替换中“成功写入数必须等于输入列表长度”的恒真比较：当前 DAO 成功后
   返回的就是输入长度，插入失败会抛异常并回滚。由成功事务确定导入数量，不增加逐行回读计数。
2. `XrayShareReader` 直接消费原生桥返回的节点列表，移除重新包成 `outbounds` Map 后再拆开
   的过程，以及只为该包装存在的动态类型分支。保留名称映射、批量让出事件循环与有效节点处理。
3. 核对空闲端口接口约定，将必要的响应结构判断留在桥接边界，移除业务层对相同保证的重复判断。
   `allocateRuntimePorts` 专注 Raw/高级额外入站的单端口及范围冲突、有界重试和实际错误传播。
4. 保留已保存 HTTP API 端口的排除，即使 API 关闭；端口选择不是占用预留，实际绑定失败仍由启动报告。
   HTTP API 的显式预览端口是外部输入，不能因自动分配的保证而删除其检查。

### 验收标准

- [x] 标准分享、Age 订阅及空结果行为不变；零有效节点不创建或覆盖订阅。
- [x] 成功数量等于实际提交的本批节点数量；任意数据库异常仍整笔回滚，不计入保护的旧节点。
- [x] 桥接失败或必要响应缺失仍明确报错，业务层没有重新搭建动态 JSON 校验链。
- [x] API 保留端口和 Raw 入站冲突测试通过；重试耗尽报错，不改写用户入站来规避冲突。

## 6. P2 统一保存与提交校验

主要入口：[隧道 controller](../lib/pages/advanced/tunnel/controller.dart)、
[平台策略编辑](../lib/service/advanced/policy_editor.dart)、
[平台策略](../lib/service/advanced/platform_policy.dart)、
[自定义路由](../lib/service/connect/routing/custom/)、
[订阅服务](../lib/service/servers/subscription/)。

### 开发步骤

1. 隧道保存由 service 负责最终策略检查和运行投影。页面只负责反馈和调用，去除紧邻的重复
   `validate`；同次保存的 DNS、Apple TUN、Windows 策略转换尽可能共享投影结果。
   不给新启动、数据库重新读取或外部输入复用旧“已验证”结论。
2. 自定义路由将名称处理、State 检查及保存检查收敛到现有业务入口。合并同一受保护提交范围
   内的重复查库，保留最终事务的上限和名称唯一检查、原记录存在/类型/内容检查。
   用户确认或排队之前的必要预检与提交时复核不可混为一谈。
3. 订阅新增和编辑共享名称、HTTPS URL、Age 成对输入等检查；所有真实写入入口都必须经过
   同一规则。现有 URL 列没有数据库唯一约束，不能先删页面检查却不给提交入口补足重复检查。
   重复 URL 检查与写入置于相应事务，不新增 schema 或通用唯一性框架。
4. UI 即时反馈复用上述纯规则；service 调用者不依赖页面先验证。保存失败保留草稿和具体原因，
   订阅编辑仍只保存来源，不下载或替换节点；HWID 生成后不因编辑重建。
5. 删除仅转发同一检查、无额外职责的方法；不要为了降低调用次数扩大队列或锁的范围。

### 验收标准

- [x] 页面和非页面入口都不能绕过 App 的名称、额度、URL、Age 或平台策略约束。
- [x] 同一保存复用策略运行投影；错误提示、loading、草稿保留和重连确认不变。
- [x] 保存等待时记录被修改、删除或额度被占满，最终提交拒绝旧草稿且不覆盖新数据。
- [x] IPv6 停用值、Apple 全流量接管下停用的排除列表等原有“保存但不应用”行为保持不变。
- [x] 订阅迟到回包、HWID 拒绝与零有效节点保旧回归通过；没有全局禁用 UI 或串行所有保存。

## 7. P3 配置解析结果复用

主要入口：[Raw 编辑](../lib/service/connect/raw/editor.dart)、
[Raw 验证](../lib/service/connect/raw/validator.dart)、
[配置交换](../lib/service/shared/share/configuration_transfer.dart)、
[路由文档解析](../lib/service/connect/routing/custom/)、
[HTTP API 配置处理](../lib/service/advanced/local_api/configuration.dart)。

### 开发步骤

1. Raw 解析一次得到原文、名称和 Map，名称调整、语义比较及验证副本消费该结果。
   消除 `namedText → normalize → decode` 的完整往返；不重排未改名原文，不丢未知字段。
2. 常规/高级路由导入在单个解析入口完成文档、字段范围及 Geodata 声明检查，传递已解析的
   State/模板和声明；HTTP API 不再先解析路由，再让交换服务重读同一文本。
3. HTTP API 和 UI 复用对应解析与验证投影，但保留各自业务差异：API 不检查数据库重名/额度，
   不下载、不保存、不选择用户节点；编译预览不调用内核，不分配真实端口或启动 VPN。
4. 保留原文位置索引与语法诊断。需要为了行列定位扫描原文不等于重复业务解析；不能通过
   删除 `JsonDocument` 破坏错误位置，不能从内核文字猜测字段位置。
5. 已解析 Map 的验证/编译均使用必要副本；UI 编辑产生新版本后重新解析，不建立跨编辑、
   跨请求缓存。异步返回仅对应提交时的草稿，不污染后来输入。

### 验收标准

- [x] Raw 保存、路由交换及 API 不再为传参进行完整 JSON 往返，也没有新增字段校验清单。
- [x] Raw 未改名时原文保持一致；高级用户字段、普通模型输出和托管字段投影与基线一致。
- [x] Geodata 声明的 HTTPS、文件名和冲突检查仍经过共同入口，不因 API 去重而绕过。
- [x] UTF-16/CRLF、根类型错误、可定位字段与不可定位内核错误均正确反馈；迟到错误不标记新草稿。
- [x] 一次显式完整配置校验仅执行一次对应内核校验；编译预览和连接启动均不增加 `testXray`。
- [x] HTTP API 四种输入、鉴权、超限、忙碌、撤销凭据及与 UI 投影一致性的现有测试通过。

## 8. P4 备份编解码去重

主要入口：[备份 codec](../lib/core/backup/codec.dart)、
[备份资产](../lib/service/settings/backup/assets.dart)、
[备份编排](../lib/service/settings/backup/service.dart)。Geodata 复用范围在 P5 处理。

### 开发步骤

1. 写出路径只对导出资产执行必要的合同检查，序列化后检查实际字节上限；删除用
   `decodeBackup` 重新读取自身编码结果来验收的往返。
2. 外部文件在读取入口完成格式、版本、必要分区、Base64/UTF-8/JSON 与资产约束检查。
   后续预览消费该结果，不再次运行整份 `validateBackupAssets`。
