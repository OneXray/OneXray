## 0. 执行规则

1. 顺序固定为 **P0 盘点 → P1 插件验证 → P2 平台接入收敛 → P3 协议 → P4 Geodata →
   P5 本地恢复 → P6 手动备份界面 → P7 自动备份 → P8 总体验收**。
   不提前接入后续阶段的生产入口；前一阶段通过适用检查后自动继续，无需重复询问。
2. 平台文件读写优先复用第 5 节指定插件。不得以统一接口、文件大小限制或潜在线程问题为由，
   未验证就自行改为整套 Swift/Kotlin/Pigeon 实现。共享 Dart 接口不等于需要自定义原生接口。
3. 原生补充必须先记录具体缺口、源码/API 证据和最小改动范围。Android 仅按第 5.2 节的条件
   补充选择与持久授权；改写 Apple 读写、更换读写插件或扩大原生职责，必须先提出计划修订并取得确认。
4. 现有草稿可复用，但须在对应阶段检查和验证；不能因文件存在或早期单测通过直接跳过验收。
   尚未验收的调度、恢复和平台桥接不应在 App 启动中提前启用。
5. 遇到实际编译/测试失败、已选插件无法满足合同、需改变协议或新增权限时，停在对应步骤，
   说明证据与建议；不得偷偷换方案或把失败记为跳过。
6. 缺少真实云账号、签名设备，或当前 macOS 无法执行 Windows 验证时，可记录明确的“待平台验收”
   后继续不依赖该环境的步骤；它不等于通过，不解除对应平台的发布阻碍。
7. 每阶段结束记录修改文件、检查命令、结果和待验收项。只验证实际风险，不为阶段包装额外框架。
   Flutter/Dart 命令全局串行；Demo 和证据放在工作空间 `references/cloud-backup/`。
8. 保护用户已有修改、主库和云文件。不得为验证重置用户数据库、覆盖现有云备份，或整文件回滚
   iCloud 配置。真实云写入测试须先明确隔离的测试目标。
9. 当前已授权按本计划实现；不自动包含 commit、push 或 PR，这些操作按用户当次授权执行。

## 1. 目标与范围

提供跨 Apple、Android、Windows 的配置备份与恢复。各平台共享一个文件协议，分别使用系统存储能力；
不建设云账号体系、双向同步或数据库复制机制。

已确定的产品边界：

- App 在当前平台只绑定一个目标，该目标只维护一份备份，新备份覆盖旧文件；不维护历史列表。
- 自动备份默认开启，支持关闭；备份周期独立保存，仅复用 Geodata 的 1/3/7 天选项，默认 3 天。
  保留手动“立即备份”和恢复，恢复始终由用户发起并确认。
- 自动备份在首次确认存储目标、敏感信息风险及后续覆盖行为后生效；未绑定/未确认时不写入，
  不因默认开启就在新安装时覆盖已有云备份。
- 文件未加密，明确提示包含节点凭据、订阅地址、Age 私钥和 HWID；Base64 不是加密。
- 只备份连接配置资产、智能路由设置和自定义 Geodata 来源，不包含任何资源文件。
- 沿用旧版范围：手动节点、Raw JSON、订阅来源；不保存订阅下载的节点缓存。
- 增加当前产品的常规/高级自定义路由和智能路由设置。
- 不备份最终出口选择。对应节点若属于手动添加，仍作为普通本地节点备份。
- 不保存首页当前选择、专家模式状态、收藏、测速结果或数据库 ID。
- 不保存 VPN 隧道、平台专属策略、日志设置、主题、语言、启动偏好、系统权限及云端授权。
- 完整替换连接配置资产，不合并、不按名称匹配节点、不重建旧 ID 关系。
- 恢复提交不依赖订阅或 Geodata 下载成功，不自动启动 VPN。

平台范围：

| 平台 | 存储方式 | 首版边界 |
| --- | --- | --- |
| iOS、macOS、macOS SE | iCloud Drive 文档容器 | 同一开发者团队下共享指定容器；不使用 CloudKit |
| Android | SAF 授权的单个文档 | 用户在系统选择器中选择 Google Drive；不接 Google OAuth/Drive REST API |
| Windows EXE、ZIP、MSIX | 用户选择的 OneDrive 同步目录 | 普通文件读写；不依赖 package identity，不接 Microsoft Graph |
| Linux | 本期不提供云备份入口 | 共享协议代码保持平台无关，不额外实现 Linux 存储方案 |

单文件是 App 的管理范围，不意味着云服务没有版本历史，也不意味着 App 能删除其它设备创建的副本。
三个平台使用相同格式不等于跨云盘同步。清理 App 数据或解除目标绑定不删除云端备份。

## 2. 协议 v1

固定建议文件名为 `OneXray-backup.json`，UTF-8 JSON，MIME 为 `application/json`。
Apple 容器相对路径为 `Documents/OneXray-backup.json`；Windows 在已选目录中使用固定文件名。
Android 以系统返回的文档 URI 为身份，展示实际文件名；不能假定提供商没有调整名称。

下面是空资产集合的结构示例：

```json
{
  "format": "onexray-backup",
  "version": 1,
  "createdAt": 1789516800000,
  "coreConfigs": [],
  "subscriptions": [],
  "routingProfiles": [],
  "smartRouting": {
    "entryCount": 1,
    "directRegions": ["CN"],
    "directPrivate": true,
    "directApple": true,
    "directWindows": true,
    "directDns": true,
    "directDnsAddress": "8.8.8.8",
    "fakeDns": false,
    "blockAds": false
  },
  "geoData": []
}
```

`version` 只表示备份协议版本；`createdAt` 为 Unix 毫秒时间戳，不用于跨设备冲突排序。
新协议不导入旧 ZIP v3/v4，不因同名 `version` 猜测旧格式，不加入兼容转换。

### 2.1 数据映射

| 分区 | 字段与来源 | 恢复规则 |
| --- | --- | --- |
| `coreConfigs` | 本地 `CoreConfig` 的 `name/type/tags/data`；`subId = 0`，类型只取 `outbound/raw` | 新 ID、`subId = 0`、未测速、无位置缓存、未收藏 |
| `subscriptions` | `name/url/ageSecretKey/agePublicKey/hwidEnabled/hwid` | 新 ID，密钥和 HWID 原样保留；未下载，不制造成功更新时间 |
| `routingProfiles` | `name/advanced/data` | 新 ID，保持类型与原文，不在常规/高级之间转换 |
| `smartRouting` | 上述示例中的九个设置 | 显式字段投影；不读取、不输出 `finalExitId` |
| `geoData` | 全部自定义来源的 `name/type/url`，包括待下载来源 | 名称不带 `.dat`；`type` 为 `domain/ip`；默认组不进入备份 |

`data` 直接保留数据库的 Base64 字符串，不解码再重新格式化，不通过普通分享链接往返转换。
读取时可以为必要校验解码，但最终存储原字符串；Raw 原文及高级路由的允许字段不能被普通模型裁剪。
空密钥/标识统一使用 null；Age 公私钥必须成对存在或同时为空。已有 HWID 即使发送开关关闭也保留。

订阅缓存、本地编辑过的订阅节点、收藏和当前选择不会恢复。不能为保留这些关系悄悄复制订阅节点为本地节点。
所有已有 Raw 都导出和恢复，包括超过三份的旧数据；恢复入口不能套用“新增 Raw 最多三份”的逐条插入限制。
自定义路由仍遵守当前产品的三份上限及名称唯一规则，不为备份新增一种路由类型。

不向各配置再次注入 `geodata.assets`。根级来源声明是本次备份的统一依赖目录；配置中原有的 ext 引用保持不变。
引用未登记的文件或证书路径不触发猜测下载地址，也不扫描凭据等任意字符串寻找文件路径。

### 2.2 必要校验

- 检查格式标识、协议版本、时间戳、必要分区和字段类型；缺失列表不是空列表。
- 检查 Base64、UTF-8、配置 JSON 对象、现有名称约束和来源字段；保持当前 Geodata 文件名安全及 HTTPS 限制。
- 复用常规/高级路由各自的存储结构边界，不自行添加 Xray 协议、算法、网络类型等重复校验。
- 不接受将 `finalExitId`、数据库 ID 或平台策略混入 v1 定义的字段；不把它们应用到目标设备。
- 未知协议版本拒绝，不部分恢复、不静默丢条目。内容为空的合法备份可以恢复，但确认文案必须说明会清空连接配置。
- 首版完整文件读写上限集中定义为 64 MiB，读取时尽可能在分配完整缓冲前限制；超过上限明确失败，不压缩、分片或裁剪。
  上限是保护文件读取的技术限制，不是 Raw 数量限制。平台适配验证必须覆盖受限读取能力。
- 恢复不以 `TestXray` 成功为前置条件，不因资源缺失拒绝整个备份；同时不能宣称恢复后配置已通过运行校验。
  后续编辑保存仍用现有校验，启动仍由现有编译/内核运行路径判断，不重加启动前 `testXray`。

## 3. Geodata：声明与安装状态分离

这是离线恢复的前置工程改动。基线中的 `GeoData` 全部被当作已发布文件，`ensureInstalled` 要求 manifest 与文件完全匹配；
直接插入一个没有文件的来源会使下一次启动失败，不能只修改备份页面绕过它。

### 3.1 最小数据库调整

计划为现有 `GeoData` 增加一个 `installed` 布尔列：

- true：已经成功发布，继续要求 DAT、索引与记录一致；不能只凭文件存在认定有效。
- false：有意登记但尚未安装的自定义来源，允许没有文件。
- 已有记录和普通成功添加/更新沿用 true；恢复时缺少有效文件的来源写 false。
- 默认 `geoip` / `geosite` 始终为已发布组，不允许用 false 隐藏默认组损坏。
- false 时旧统计字段使用未安装占位值（时间戳 epoch、数量 0），UI 和调度以 `installed` 判断，
  不把占位值显示为上次成功更新或有效分类数量。下载成功后一次提交真实时间、数量和 true。
- 不新增 generation、持久化下载进度、错误历史、配置级“已校验”标记或另一张来源表。

这一列保存的是“允许缺文件的意图”，不能仅靠每次检查文件存在推导，否则无法区别待下载与意外损坏。

实施前重新核对发布边界：按当前基线，将列并入尚未发布的 schema 5 及正式旧库 v1–v4 的升级路径，
不另升 schema 6，不写开发库 v5→v5 的修补逻辑。若 schema 5 已在实施前正式发布，则必须重新规划正式升级。
不自动删除开发者的现有数据库；开发库验证使用隔离安装或取得明确授权后的重建。

### 3.2 启动、列表与发布

- DAO 分清全部来源与已发布来源；校验 manifest、分类索引和补全只读取已发布记录。
- Geodata 页面同时展示已发布和待下载来源。待下载行没有文件大小、成功时间、分类详情，提供下载/重试及删除。
- 保留已发布行现有设计，不给每个成功项新增“可用”标签。
- 待下载记录不能使 `ServiceManager` 或页面初始化失败。原本已发布文件的意外损坏仍按现行合同报错。
- 根目录完整丢失/为空时仍由正常初始化发布内置默认组；新增的待下载声明应保留，不能被既有全表重置一并删除。
  仅数据库本身丢失时，不能从文件猜回丢失的来源声明。
- 待下载项进入现有自定义下载、libXray 索引和文件发布流程；下载失败保留 false，成功后变 true。
- 所有读取、发布和删除继续使用 `GeoDataService.withFiles`，维持唯一平铺目录，不建立第二套运行资源目录。
- 配置分享可以使用待下载来源的声明生成依赖链接；域名/IP 分类自动补全不能读取不存在的索引。
- 普通添加 Geodata 和独立配置导入保留当前成功后发布规则，不因为备份功能普遍放宽它们的校验与下载流程。

### 3.3 恢复时的文件处理

只复用名称、类型、URL 一致且通过现有本地发布检查的文件。缺失来源登记为待下载，不联网。
同名但不同类型/来源视为替换冲突，在恢复预览中列出；用户确认完整替换后，不得让旧文件冒充新来源。
备份中未列出的旧自定义来源被移除，默认组保留。

文件移除/失效处理与数据库替换共用已有 Geodata 文件事务及回滚能力；不得先无条件删除整个 dat 目录。
对移动到本地暂存区的旧文件补齐最小冷启动恢复边界：数据库未提交则恢复旧发布，已提交则完成清理，
不能遗留会使 manifest 校验失败的 orphan 文件。只暂存本次变更涉及的文件，不复制 SQLite、不建立完整 App 快照。
这里的本地事务暂存不属于云端备份内容。

### 3.4 网络不可用与连接行为

- 默认路由数据使用目标设备已有有效文件或 App 内置资源，恢复过程中不更新默认组。
- 缺少自定义数据只影响依赖它的配置。沿用语义位置的 ext 引用扫描，展示缺失文件名，不能静默删规则或改走直连。
- 在连接准备阶段检查被选配置所需的已登记资源；这是本地依赖检查，不调用 `testXray`，不下载、不修改 VPN 状态。
- 用户可以先用不依赖自定义文件的模式连接，再手动下载。
- 自动下载复用已有连接成功后的延迟检查及自动更新开关；待下载项视为需要获取，不受成功更新时间占位值干扰。
  未连接时不自动下载，不新增轮询/重试循环，不绕开用户关闭的自动更新开关。
- 失败保留旧有效文件或待下载声明，不断开 VPN、不重连。证书等非 Geodata 外部文件仍需用户另行准备。
- 如果只有订阅来源而订阅也无法访问，可能没有可用节点。这是“不备份订阅缓存”的明确限制，不通过暗中备份缓存解决。

## 4. 备份与恢复业务流程

### 4.1 生成和覆盖备份

1. 在一次只读数据库事务中读取所有备份分区；不暂停 VPN，不等待测速或下载结束。
2. 在事务外构造完整字节内容并做协议自检；较大的编解码离开 UI isolate。
3. 首次确认敏感信息、目标及后续覆盖行为后，手动和自动备份复用同一写入流程，不为每次自动备份弹出确认。
   写入前重新核对当前目标和操作许可；确认/系统选择器/云 I/O 不占用数据库事务或 Geodata 文件队列。
4. 成功仅表示本地容器/文档提供商接受写入；界面提示后续同步由系统负责，不声称云端已经上传完成。

先准备完整内容再开始覆盖，不主动删除旧目标。Apple 使用协调替换；Windows 使用同目录暂存和支持替换的文件操作。
Android 使用同一文档 URI 覆盖，提供商的原子性不由 App 保证：中断可能损坏旧文档，不能宣传“失败一定保留旧云备份”。
不得用临时云端副本、时间戳文件或反复新建文档冒充单文件更新。

### 4.2 本地恢复提交

1. 完整读取并校验文件，生成资产数量、待下载资源和同名冲突的预览；不修改数据库、不停止 VPN、不下载依赖。
2. 用户确认“替换连接配置，并停止当前 VPN”。空资产备份单独明确其清空效果；取消不产生业务副作用。
3. 使用仅供清理/恢复的互斥入口，暂停自动备份、自动更新、节点导入、订阅下载、测速、Geodata 更新及连接命令，
   先同时暂停接收，再等待已开始操作结束；不等待全部排队测速，不让旧回调在恢复后回写。
4. 取得文件协调范围，调用 `ConnectionCoordinator.stopForMaintenance` 并确认停止。失败则不替换数据。
5. 在同一数据库事务中完整替换本地节点/Raw、订阅、路由及自定义来源，删除旧订阅缓存和退休配置行。
   生成新记录 ID，不重置 SQLite 自增序列以复用旧 ID；配合现有草稿冲突检查，拒绝迟到编辑覆盖新数据。
   提交前重新读取可复用的 Geodata 发布状态；若相对预览新增了同名来源冲突，则重新确认，不能沿用过期预览静默处理。
6. 只替换 `ConnectionConfiguration.connection`，保留提交时读取的 `policy`。
   新连接设置为普通模式、自动选择、智能路由；保留备份 Smart 设置，强制最终出口为空，Raw/Custom 当前 ID 为空。
7. 文件与数据库失败走现有局部回滚；无法确认回滚完整时明确报告，不无条件声称原数据完整保留。
8. 清除内存中的旧流量/测速错误/运行选择展示，防止旧运行描述被重新当成已连接；最后恢复各模块接收新操作。
   不清理 App Preferences、不注销登录项、不删除系统 VPN 配置、不重跑 Setup、不重新授权、不自动重连。

不能直接调用 `AppDataCleanupService.clearFromSettings`：它会清理偏好、登录项和默认资源，超出恢复范围。
可以抽取其必要的暂停/恢复协调，限定为清理和恢复两种破坏性操作；不重新引入全局 `DataMaintenance`，
不要求普通保存/测速/下载都进入同一队列。页面仍可导航，冲突写操作在服务入口明确拒绝，而非全局禁用 UI。

### 4.3 提交后的独立任务

- 配置提交成功立即报告恢复完成及待下载资源数，不等待订阅下载或测速。
- 恢复动作可以提交一次订阅刷新，复用已有来源更新流程；逐来源结果独立报告，失败保留来源，允许重试。
  手动节点的补测使用现有测速队列，不能再次成为恢复成功条件。
- Geodata 不在恢复提交后立即强制下载，继续按上一节的手动/已连接自动更新规则执行。
- 不持久化“后续任务队列”。App 中断后依靠已保存来源、待下载状态及原有检查重新发现需要处理的内容。
- 目标设备的启动偏好保留，但恢复不能重触发本次进程的自动连接。

### 4.4 自动备份调度

自动备份复用现有生命周期检查入口，但与 Geodata 下载保持独立：周期配置、开关、成功时间及 VPN 条件互不影响。

- “自动备份”默认 true，本机独立保存开关与备份周期。周期默认 3 天，可选 1 天、3 天、7 天；
  只复用 `AutoUpdateInterval` 的时间选项，不读取 `AutoUpdateState.geoDataInterval`，不从 Geodata 继承初始值。
  修改任一周期不影响另一功能；修改备份周期不立即写入，下次正常检查按新周期判断到期。
- 关闭 Geodata 自动更新不关闭自动备份；关闭自动备份也不影响 Geodata。备份不要求 VPN 已连接，
  不因正在测速、订阅下载或 Geodata 更新而跳过；普通读取使用一致的数据库事务即可。
- 服务就绪后的启动检查、回到前台、现有每小时检查和连接成功后的延迟检查分别触发到期判断。
  在现有 `BackgroundTaskService` 中分发独立任务，不把备份放进 `DataUpdateService` 的
  VPN/`downloading` 条件内，不等待订阅或 Geodata 更新结束再备份；各自失败不阻断另一项。
- 首次使用时明确提示未加密与自动覆盖风险。仅打开页面、选中已有文件或读取恢复文件不授予自动覆盖许可。
  确认启用当前目标后，若自动备份开启且尚无成功记录，则执行首次备份；更换目标必须重新确认。
  Apple 虽使用固定容器，也遵守首次确认规则，不在新安装时静默覆盖其它设备留下的备份。
- 以当前目标在本机的上次成功写入时间判断到期，手动备份成功同样重置周期。
  失败不推进成功时间；自动尝试按最近一次尝试时间至少间隔一小时，复用下一次正常检查重试，
  不增加重试定时器或积压任务队列。手动“立即备份”不受周期和自动重试节流限制。
- 目标绑定、覆盖确认、自动开关、备份周期、成功/尝试时间仅保存在本机 Preferences，不进入备份协议。
  更换目标清除旧目标的调度记录，保留自动开关与周期；清理 App 数据清除这些本机设置，不删除云文件。
  恢复连接配置保留这些本机设置，不隐式授予覆盖许可、不伪造备份成功时间，也不立即触发一次备份。
- 同一时刻只执行一次备份或恢复；重复自动检查直接合并，不排队补做每个错过的周期。
  清理/恢复暂停新备份并等待已开始的写入结束，恢复后在下一次正常检查重新判断；不能在资产替换中途取样。
- 关闭开关立即阻止尚未开始的自动写入，已经提交给文件提供商的写入允许结束，避免截断文件。
  目标变更与写入互斥，异步结果不得被记到新目标上；这些限制只作用于备份模块，不锁住整个 App。
- 自动成功不弹 toast；失败保留本机可查看的具体原因及手动重试入口，不反复弹窗、不强制显示窗口，
  不修改 VPN 状态，也不因备份失败使服务初始化失败。

周期表示 App 有执行机会时的到期检查，不承诺进程退出或被系统挂起后仍准点执行。
桌面 App 留在托盘时可沿用现有定时检查；移动端恢复运行后补查一次即可，不引入新的系统后台任务或常驻服务。
文件写入后的云端同步仍由系统/提供商负责，不能把本机成功时间当成云端上传完成时间。

## 5. 平台存储接入

共享层仅统一读取字节、覆盖字节、当前目标与操作结果；目标选择、权限和云同步状态保持平台特有语义。
目标绑定只保存在本机 Preferences，不进入备份。备份模块自身防止重复备份/恢复，不建立跨业务全局 I/O 锁。

### 5.1 Apple

使用 `icloud_storage_plus`，基于已检查的 4.0.0 API 接入并在 lockfile 固定实际解析版本。
复用 `readInPlaceBytes` / `writeInPlaceBytes` 的协调读写与覆盖，不新增 Apple 备份读写 Pigeon API，
不保留本轮草稿中的 `CloudBackupHostApi` 作为备用实现。不为了接入顺带升级其它插件。

- 固定使用用户提供的 `iCloud.net.yuandev.onexray`，相对路径为 `Documents/OneXray-backup.json`。
  iOS、macOS、macOS SE 共用该容器，不修改 Network Extension 的职责。
- 保留用户已配置的 entitlements；核对容器展示用 Info.plist、插件注册、签名及 provisioning。
  不能把源码中存在 entitlement 等同于实际签名和账号访问已通过。
- 到期判断只读取本机偏好，不在启动、进入设置页或循环轮询中探测云端文件元数据。
  仅已确认目标的到期自动备份，以及明确的手动备份/恢复动作触发云访问。
- 只核查实际使用的读写路径、占位文件取回及线程行为。
  [上游问题 #48](https://github.com/Jason-Holt-Digital/icloud_storage_plus/issues/48) 仍未关闭；
  4.0.0 的 `getItemMetadata` 会在 MainActor 中执行同步文件检查。仅在手动恢复时预检一次可以减少触发，
  但不能消除阻塞风险；Dart worker isolate 也不能改变插件内部的线程安排。
  不直接据此判断全部读写不可用，不删除 MainActor 标注或自写第二套原生 I/O。
- 4.0.0 的 `readInPlaceBytes` 会整文件读入，不提供 `maxBytes` 参数。64 MiB 是 App 的接受上限，
  不是该插件保证的原生读取上限；在 P1 核对可用的单次大小预检，读取后仍须检查实际字节长度。
  若无法在完整分配前限制，须记录这一限制与实测结果；不得声称已经具备流式限额保护。
 如该限制或实际卡顿影响安全使用，停止 Apple 接入并提出局部修复方案，不擅自更换实现。
- `icloudAvailable()` 仅表示账号能力，不证明指定容器权限正确；读写成功只表示本地文档操作完成，
  不表示云端已同步。不增加轮询、目录遍历、版本合并或下载就绪状态机。
- 不直接修改 pub cache；未经确认不 fork 插件或增加自写 Apple 读写后备路径。
- 未登录、容器不可用、权限/签名缺失、空间不足、文件尚未下载等错误可操作地反馈，不回退到另一个静默本地备份。

配置依据：[Apple iCloud 配置文档](https://developer.apple.com/documentation/xcode/configuring-icloud-services)。

### 5.2 Android

采用 SAF 单文档；使用 `saf_stream` 读写，基于已检查的 4.0.1 API 接入并锁定实际版本。
读取固定采用 `startReadCustomFileStream` / `readCustomFileStreamChunk` / `endReadCustomFileStream`，
每次 64 KiB，Dart 层累计限额并在 finally 关闭；JNI 拉取放到 worker isolate。
不使用 `readFileBytes(count:)` 的单次底层 read 充当完整读取，也不使用无背压的自动 stream pump。
覆盖固定使用 `writeFileUriBytes(uri, bytes, append: false)`，复用同一 URI 的截断写入。
不在 App 的 Kotlin/Pigeon 中重写这些内容读写能力。

P1 已核实选择与持久授权缺口：`saf_stream` 不提供；`saf_util 3.1.0` 单文件选择不能完整覆盖；
`android_file_picker` 的打开分支仅部分满足，创建分支返回 URI path 且未完整持久授权，2.0.0 仍如此。
因此保留三个 Android 专用 Pigeon 方法：`selectBackupFile(create)`、`requireBackupAccess(uri)`、
`releaseBackupFile(uri)`。前者返回完整 URI 和实际文件名，取消返回 null；后两者仅管理授权。
不追加 native 内容读写、云同步、定时器、广泛存储权限或前台服务。

- 首次提供“选择已有备份”与“创建备份文件”；系统选择器中可选择 Google Drive，不要求整目录授权或广泛存储权限。
- 使用 `ACTION_OPEN_DOCUMENT` / `ACTION_CREATE_DOCUMENT`，保留原始 `content://` URI 与实际返回的读写权限。
- 调用并验证持久授权，明确检查 `persistedUriPermissions` 中的读写许可；只读 URI 不能当成可覆盖目标。
- 之后始终对同一 URI 写入，不能使用缓存文件路径，不得把 URI 的 `path` 当作完整 URI。
- `ACTION_CREATE_DOCUMENT` 不是覆盖接口，同名时可能创建编号副本；仅用户明确新建时调用。
  App 不遍历云盘删重复文件，不宣称能保证其它设备从未新建副本。
- 返回文件名和授权事实；用户取消不修改旧绑定。更换成功后只释放 App 旧绑定对应的授权，不撤销其它文件导入授权。
- 文档移动/删除、授权撤销、重装后授权丢失时要求重新选择，不自动创建替代文件。
- 文件创建可能在写入失败后留下空文档，必须明确提示，不将其标记为成功备份，也不随意删除用户已有文档。
- 检查 saf_stream 的 JNI、Flutter/Dart、Gradle 兼容性；在真实 Drive 提供商验证覆盖与重启后授权。

依据：[Android SAF 文档](https://developer.android.com/training/data-storage/shared/documents-files)、
[saf_stream URI I/O](https://pub.dev/packages/saf_stream/versions/4.0.1)。
已有调研对 `android_file_picker` 的保存返回值/持久授权提出过疑问；P1 以实际使用版本的源码
和返回结果作结论，不把候选包的限制扩大成“所有插件都不能用”。

### 5.3 Windows

- 复用已有 `file_picker` 选择同步目录，普通文件读写覆盖固定文件；EXE、ZIP、MSIX 共用实现。
- 不硬编码用户目录/OneDrive 路径，不要求微软应用注册、租户、OAuth 或 Graph 权限。
- 首次选择已有备份所在目录时不自动覆盖；用户可先读取、预览和恢复，再明确允许后续手动/自动覆盖。
- 完整内容先写到同目录暂存文件，再使用可靠的替换操作；不能通过先删旧文件实现覆盖。
  核对 Dart 在 Windows 的实际替换行为，必要时复用现有 win32 依赖，而非假设所有平台的 rename 一样。
- 目录不存在、文件锁、磁盘满、权限不足、OneDrive 占位文件离线不可读时报告实际错误，不创建猜测目录。
- App 只报告本地文件写入完成。OneDrive 的登录、同步、上传重试由系统客户端处理。
- 在当前 macOS 主机只做静态与共享合同检查，不尝试构建/运行 Windows；三个分发模式留 Windows 人工验收。

## 6. 页面与状态

在设置的“数据”区域增加“备份与恢复”详情页，移动端与桌面端共享业务控制器。

- 页面使用现有系统 AppBar、主题、响应式布局和固定底部操作组件；不增加页面内假导航。
- 展示当前平台存储位置、未加密警告及范围说明；Android/Windows 提供首次选择与更换位置。
- 增加默认开启的“自动备份”开关；未确认目标时显示“待设置备份位置/确认”，不能把默认开启显示为已开始备份。
- 备份页直接提供 1/3/7 天的周期选择，选中即保存，仅对自动备份生效；关闭自动备份后仍可预先调整周期。
  保存显示行内 loading 和成功提示，不跳转到“数据更新”。Geodata 周期控件只受自己的开关影响。
- 两个主要动作为“立即备份”“恢复”；自动备份关闭后仍可手动备份。
  恢复先读取预览，再明确确认替换。选择目标本身不触发备份，首次确认后才开始使用该目标。
- 同一次页面操作有按钮内 loading、防重复提交；系统选择器取消静默完成，不全局 disable 页面。
- 云文件读写用备份模块自己的状态，不冒用测速状态。实际订阅/Geodata 下载仍发布到统一 `downloading`。
- 预览/结果区显示数量、备份内创建时间、待下载项、冲突和具体失败原因，不展示私钥或完整订阅凭据。
- 成功提示明确区分“文件已写入，系统负责同步”“配置已恢复，仍有资源待下载”，不使用笼统“云端同步成功”。
- 展示本机上次成功备份时间和最近一次失败原因；自动操作安静更新状态，只有用户主动操作才按现有规则反馈结果。
- 不为后台上传建进度轮询，不把本机“上次写入时间”冒充跨设备“最新云备份时间”。
- 使用 PageCubit/Bloc；需要新增文案时同步五种 ARB，既有文案直接复用。保留 RTL、长路径换行和 URL 的 LTR 显示。
- iCloud/Drive/OneDrive 账号或提供商不可用时保留原因与重新选择/重试入口；Linux 不展示无实现的按钮。

前置：读取本文件、根 `AGENTS.md` 及相关当前合同，检查最新 Git 状态和正式发布边界。

## 10. 验证矩阵与发布边界

### 10.1 自动验证重点

1. 协议：完整/空备份、未知版本、分区缺失、非法 Base64/UTF-8、大小上限、中文名称、Raw 原文、两种路由、旧 Raw 超额。
2. 范围：只导出本地 outbound/raw；保留关闭状态下 HWID；不重新生成 Age 密钥；排除最终出口、ID、缓存和偏好。
3. 升级：正式 v1/v2/v3/v4→目标 schema，新建库与重复打开；旧节点、密钥、HWID 和路由原文不变。
4. Geodata：pending 无文件、有效同源复用、同名异源、非法文件名、部分损坏、默认组缺失、dat 根目录丢失但 pending 声明保留。
5. 恢复：停止失败、事务失败、文件操作失败、进程在本地文件暂存/DB 提交边界中断；确认前无副作用，失败不自动重启旧 VPN。
6. 并发：订阅回包/测速/导入与恢复交错、重复自动备份、双重恢复、清理与备份/恢复冲突、迟到编辑和外部快捷启停；
   旧结果不写回新资产，不在恢复中途自动覆盖云文件，切换目标不串写。
7. 网络：所有下载失败仍完成本地恢复；pending→手动成功发布；VPN 断开或自动更新关闭不自动下载；单源失败不阻断其它来源。
8. UI：首次绑定、取消、未加密/覆盖确认、自动开关和独立周期选择、空备份、长错误、恢复完成但资源待下载、行级 loading、离页后不弹迟到确认。
9. 自动备份：默认开启、未确认不写、关闭后仅手动、首次确认即备份、与 Geodata 周期互不影响、手动成功重置周期、失败不推进成功时间及一小时节流。
   覆盖无 VPN、Geodata 自动更新关闭、下载进行中、启动/恢复前台/每小时/连接边沿、挂起后补查和清理/恢复暂停；不依赖下载成功。
